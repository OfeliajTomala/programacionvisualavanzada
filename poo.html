PROGRAMACIÓN ORIENTADA A OBJETOS


¿Qué es la Programación Orientada a Objetos?

La Programación Orientada a Objetos (POO) es un paradigma de programación que organiza el código alrededor de objetos en lugar de funciones y lógica. Un objeto es una entidad que combina datos (atributos) y comportamientos (métodos) relacionados.

La POO se basa en cuatro principios fundamentales:

Encapsulamiento

Ocultar los detalles internos y proteger los datos

Herencia

Crear nuevas clases basadas en clases existentes

Polimorfismo

Objetos diferentes responden al mismo mensaje de forma distinta

Abstracción

Simplificar la realidad extrayendo sus características esenciales


Clases y Objetos

Clases

Una clase es una plantilla o molde que define las características y comportamientos que tendrán los objetos creados a partir de ella.

Objetos

Un objeto es una instancia concreta de una clase. Si la clase es el plano, el objeto es la casa construida.


Los 4 Pilares de la POO

Encapsulamiento

El encapsulamiento es el principio de ocultar los detalles internos de un objeto y exponer solo lo necesario a través de una interfaz pública.

  • Protege los datos internos
  • Permite cambiar la implementación sin afectar a quien usa el objeto
  • Mejora la seguridad y mantenibilidad

Ejemplo en Kotlin:

class CuentaBancaria {
    // Atributo privado (encapsulado)
    private var saldo: Double = 0.0
    
    // Métodos públicos para interactuar con el saldo
    fun depositar(cantidad: Double) {
        if (cantidad > 0) {
            saldo += cantidad
            println("Depósito exitoso. Saldo actual: $saldo")
        }
    }
    
    fun retirar(cantidad: Double): Boolean {
        if (cantidad > 0 && cantidad <= saldo) {
            saldo -= cantidad
            println("Retiro exitoso. Saldo actual: $saldo")
            return true
        }
        println("Fondos insuficientes")
        return false
    }
    
    fun consultarSaldo(): Double {
        return saldo
    }
}

// Uso
val miCuenta = CuentaBancaria()
miCuenta.depositar(1000.0)
// miCuenta.saldo = 5000  // ERROR: saldo es privado

Herencia

La herencia permite crear nuevas clases (hijas) basadas en clases existentes (padres), reutilizando y extendiendo su funcionalidad.

  • Reutilización de código
  • Jerarquía de clases
  • Extensibilidad del sistema

Ejemplo en Kotlin:

// Clase padre
open class Vehiculo(val marca: String, val modelo: String) {
    fun arrancar() {
        println("El vehículo $marca $modelo ha arrancado")
    }
    
    open fun detener() {
        println("El vehículo se ha detenido")
    }
}

// Clase hija que hereda de Vehiculo
class Automovil(marca: String, modelo: String, val puertas: Int) 
    : Vehiculo(marca, modelo) {
    
    fun abrirMaletero() {
        println("Maletero abierto")
    }
    
    override fun detener() {
        println("El automóvil $marca $modelo se ha detenido con frenos ABS")
    }
}

// Clase hija diferente
class Motocicleta(marca: String, modelo: String, val cilindrada: Int) 
    : Vehiculo(marca, modelo) {
    
    fun hacerCaballito() {
        println("¡Caballito!")
    }
}

// Uso
val miAuto = Automovil("Toyota", "Corolla", 4)
miAuto.arrancar()  // Método heredado
miAuto.abrirMaletero()  // Método propio

3. Polimorfismo

El polimorfismo permite que objetos de diferentes clases respondan al mismo mensaje (método) de manera diferente.

Tipos de Polimorfismo

  • Polimorfismo de subtipo: Métodos con misma firma en clases diferentes
  • Polimorfismo paramétrico: Genéricos
  • Sobrecarga: Múltiples métodos con mismo nombre pero diferentes parámetros

Ejemplo en Kotlin:

// Clase base
open class Animal(val nombre: String) {
    open fun hacerSonido() {
        println("El animal hace un sonido")
    }
}

// Clases hijas con polimorfismo
class Perro(nombre: String) : Animal(nombre) {
    override fun hacerSonido() {
        println("$nombre dice: ¡Guau guau!")
    }
}

class Gato(nombre: String) : Animal(nombre) {
    override fun hacerSonido() {
        println("$nombre dice: ¡Miau miau!")
    }
}

class Pajaro(nombre: String) : Animal(nombre) {
    override fun hacerSonido() {
        println("$nombre dice: ¡Pío pío!")
    }
}

// Uso polimórfico
val animales = listOf(
    Perro("Rex"),
    Gato("Mishi"),
    Pajaro("Piolín"),
    Animal("Genérico")
)

for (animal in animales) {
    animal.hacerSonido()  // Cada animal responde diferente
}

4. Abstracción

La abstracción consiste en simplificar la realidad extrayendo solo las características esenciales de un objeto, ignorando los detalles irrelevantes. Se logra mediante:

  • Clases abstractas
  • Interfaces
  • Métodos abstractos

Ejemplo en Kotlin:

// Clase abstracta (no se puede instanciar directamente)
abstract class Figura {
    // Método abstracto (sin implementación)
    abstract fun calcularArea(): Double
    
    // Método concreto (con implementación)
    fun describir() {
        println("Esta es una figura geométrica")
    }
}

// Clases concretas que implementan la abstracción
class Rectangulo(val base: Double, val altura: Double) : Figura() {
    override fun calcularArea(): Double {
        return base * altura
    }
}

class Circulo(val radio: Double) : Figura() {
    override fun calcularArea(): Double {
        return Math.PI * radio * radio
    }
}

// Uso
val figuras = listOf(
    Rectangulo(5.0, 3.0),
    Circulo(2.0)
)

for (figura in figuras) {
    println("Área: ${figura.calcularArea()}")
    figura.describir()
}

Programación Orientada a Objetos

¿Cómo modelar problemas usando objetos?

El proceso de modelado orientado a objetos sigue estos pasos:

1. Identificar Objetos

Busca sustantivos en la descripción del problema. Cada sustantivo importante puede ser un objeto.

Ejemplo: En un sistema de una Biblioteca: Usuario,Libro,Prestamo.

2. Definir Atributos

Para cada objeto, identifica sus características (adjetivos).

Ejemplo:
• Libro: Título, Autor, ISBN, Año de publicación, Disponibilidad
•Usuario: Nombre, ID, Correo electrónico, Teléfono, Fecha de registro

3. Identificar Comportamientos

Busca verbos asociados a cada objeto (qué puede hacer).

Ejemplo:
• Usuario: tomarPrestado(), devolver()
• Libro: prestar(), marcarComoDisponible()
• Biblioteca: registrarUsuario(), buscarLibro()

4. Establecer Relaciones

Determina cómo se relacionan los objetos entre sí.

Ejemplo:
• Un Usuario tiene Préstamos
• Un Préstamo contiene un Libro
• La Biblioteca gestiona Libros y Usuarios


Ejemplo Completo: Sistema de Biblioteca


class Libro(val titulo: String, val autor: String, val ISBN: String) {
    var disponible: Boolean = true
    
    fun prestar(): Boolean {
        if (disponible) {
            disponible = false
            return true
        }
        return false
    }
    
    fun devolver() {
        disponible = true
    }
}

class Usuario(val nombre: String, val id: String) {
    val librosPrestados = mutableListOf()
    
    fun tomarPrestado(libro: Libro): Boolean {
        if (libro.prestar()) {
            librosPrestados.add(libro)
            return true
        }
        return false
    }
}

// Crear interacciones entre objetos
val libro1 = Libro("Cien años de soledad", "G. Márquez", "123-456")
val usuario1 = Usuario("Ana García", "U001")

if (usuario1.tomarPrestado(libro1)) {
    println("Préstamo exitoso")
}

Ejercicios Prácticos

Ejercicio 1: Sistema de Figuras Geométricas

Problema: Crea un sistema para calcular áreas y perímetros de diferentes figuras geométricas usando los principios de POO.

Requisitos:

  • Usar una clase abstracta Figura con métodos abstractos calcularArea() y calcularPerimetro()
  • Crear al menos 3 clases hijas (Triangulo, Rectangulo, Circulo)
  • Implementar polimorfismo para manejar diferentes figuras
  • Usar encapsulamiento para proteger los atributos

Solución:

// Clase abstracta (Abstracción)
abstract class Figura {
    abstract fun calcularArea(): Double
    abstract fun calcularPerimetro(): Double
    
    fun describir() {
        println("Figura geométrica - Área: ${calcularArea()}, Perímetro: ${calcularPerimetro()}")
    }
}

// Clase Rectangulo (Herencia)
class Rectangulo(private val base: Double, private val altura: Double) : Figura() {
    // Encapsulamiento: atributos privados
    
    override fun calcularArea(): Double {
        return base * altura
    }
    
    override fun calcularPerimetro(): Double {
        return 2 * (base + altura)
    }
}

// Clase Circulo (Herencia)
class Circulo(private val radio: Double) : Figura() {
    override fun calcularArea(): Double {
        return Math.PI * radio * radio
    }
    
    override fun calcularPerimetro(): Double {
        return 2 * Math.PI * radio
    }
}

// Clase Triangulo (Herencia)
class Triangulo(private val lado1: Double, private val lado2: Double, 
                private val lado3: Double, private val altura: Double) : Figura() {
    
    override fun calcularArea(): Double {
        return (lado1 * altura) / 2
    }
    
    override fun calcularPerimetro(): Double {
        return lado1 + lado2 + lado3
    }
}

// Uso con Polimorfismo
fun main() {
    val figuras: List = listOf(
        Rectangulo(5.0, 3.0),
        Circulo(2.0),
        Triangulo(3.0, 4.0, 5.0, 2.4)
    )
    
    // Polimorfismo: cada figura responde de manera diferente
    for (figura in figuras) {
        figura.describir()
    }
}

Ejercicio 2: Sistema de Empleados

Problema: Modela un sistema de nómina para diferentes tipos de empleados en una empresa.

Requisitos:

  • Clase base Empleado con atributos comunes (nombre, id, salarioBase)
  • Clases hijas para diferentes tipos: EmpleadoTiempoCompleto, EmpleadoPorHoras, Gerente
  • Cada tipo calcula su salario de manera diferente
  • Implementar un método polimórfico calcularSalario()
  • Agregar un bono especial para Gerente

Solución:

// Clase base (Abstracción)
open class Empleado(val nombre: String, val id: String, protected val salarioBase: Double) {
    // Método que será sobrescrito (Polimorfismo)
    open fun calcularSalario(): Double {
        return salarioBase
    }
    
    fun mostrarInformacion() {
        println("$nombre (ID: $id) - Salario: $${calcularSalario()}")
    }
}

// Empleado de tiempo completo (Herencia)
class EmpleadoTiempoCompleto(nombre: String, id: String, salarioBase: Double) 
    : Empleado(nombre, id, salarioBase) {
    
    override fun calcularSalario(): Double {
        return salarioBase  // Salario fijo mensual
    }
}

// Empleado por horas (Herencia)
class EmpleadoPorHoras(nombre: String, id: String, val horasTrabajadas: Double, 
                       val tarifaPorHora: Double) : Empleado(nombre, id, 0.0) {
    
    override fun calcularSalario(): Double {
        return horasTrabajadas * tarifaPorHora
    }
}

// Gerente (Herencia con funcionalidad adicional)
class Gerente(nombre: String, id: String, salarioBase: Double, 
              val bono: Double) : Empleado(nombre, id, salarioBase) {
    
    override fun calcularSalario(): Double {
        return salarioBase + bono
    }
    
    fun dirigirReunion() {
        println("$nombre está dirigiendo una reunión")
    }
}

// Sistema principal
fun main() {
    val empleados = listOf(
        EmpleadoTiempoCompleto("Ana López", "E001", 2500.0),
        EmpleadoPorHoras("Carlos Ruiz", "E002", 160.0, 15.0),
        Gerente("María García", "G001", 4000.0, 1000.0)
    )
    
    println("=== NÓMINA DE EMPLEADOS ===")
    // Polimorfismo: cada empleado calcula su salario de manera diferente
    for (empleado in empleados) {
        empleado.mostrarInformacion()
    }
    
    // Uso específico de Gerente
    val gerente = empleados[2] as Gerente
    gerente.dirigirReunion()
}

Beneficios y Aplicaciones de la POO

Beneficios

  • Reutilización de código: Las clases se pueden usar múltiples veces
  • Mantenibilidad: Fácil de modificar y extender
  • Modularidad: Cada objeto es independiente
  • Seguridad: Encapsulamiento protege los datos
  • Flexibilidad: Polimorfismo permite adaptabilidad

Aplicaciones Reales

  • Interfaces Gráficas: Botones, ventanas, menús como objetos
  • Videojuegos: Personajes, objetos, escenarios
  • Sistemas Bancarios: Cuentas, clientes, transacciones
  • Redes Sociales: Usuarios, publicaciones, mensajes
  • Aplicaciones Móviles: Pantallas, componentes UI

Comparación POO vs Programación Estructurada

Aspecto Programación Estructurada Programación Orientada a Objetos
Enfoque Funciones y procedimientos Objetos y sus interacciones
Datos Separados de las funciones Integrados en objetos (atributos)
Reutilización Limitada a funciones Alta (clases, herencia)
Mantenimiento Difícil en sistemas grandes Más fácil y organizado
Ejemplo Lenguaje C Java, C++, Kotlin, Python
